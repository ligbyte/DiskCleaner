# 2026-10-15 · 概览页磁盘卡片重做 + 顶栏主题分段控件

## 概览页「磁盘占用」卡片（参考系统资源管理器的盘符卡片）
版式：**左边一块大图标（80×80），右边自上而下三行** —— 磁盘名 + 已用百分比、
整行铺满的占用条、容量明细。图标与右侧内容垂直居中。

- 图标用 `assets/disk1.png`（3D 硬盘），`include_bytes!` 编进可执行文件，
  懒加载后缓存在新增的 `App::disk_tex` 上（和 `logo_tex` 同一套路）。
- 裁掉四周透明留白的解码逻辑原本叫 `chrome::decode_logo`，改名
  `pub(crate) decode_icon_png`，顶栏品牌图标与磁盘卡片共用。
- 新增 `sysutil::volume_label(mount)` / `sysutil::disk_title(mount)`：
  标题照资源管理器的写法 `系统 (C:)` / `根分区 (/)`，括号里是挂载点本身。
  Windows 走 `GetVolumeInformationW`，盘符统一大写。
- 原来的 `big_number` 组件没人用了，删掉。
- **踩坑**：切页时 `--dryrun` 等一切正常，但新卡片渲染出来**占用条比标题行短一截**。
  原因是标题行里那个 `with_layout(right_to_left)` 扩展布局会把父 `Ui` 的可用宽度
  吃掉一块，后面 `usage_bar` 用 `ui.available_width()` 就少了。**修法**：进卡片前先
  算好 `text_width = 卡片内容宽 - 图标 - 间距`，在右侧 `ui.vertical` 里
  `ui.set_width(text_width)` 显式定宽，三行右边界才会严格对齐。

## 顶栏「跟随系统 / 浅色 / 深色」改成分段控件
`chrome.rs::theme_switch()`，**整体自绘**（不用一排 Button 拼）：
- 外层一个 `p.inset` 色的胶囊容器，选中的那一段是浮在容器内边距里的
  `p.surface` 圆角块，未选中段落是透明底 + `p.text_weak` 文字。
- 三段**等宽**：先用 `painter.layout_no_wrap()` 量一遍所有标签，取最宽的那个
  加左右留白。所以滑动块不会忽大忽小。
- 命中：`response.interact_pointer_pos()` 落在哪段就切哪段。
- 尺寸：**HEIGHT 39.0 / PAD 4.0 / SIDE 15.0 / 字号 13.0**（用户要求高度为
  最初 26.0 的 1.5 倍）。
- **API 坑**：`Context::fonts()` 给的是 `&Fonts`（不可变），`layout_no_wrap`
  要 `&mut`，会报 E0596；改用 `Painter::layout_no_wrap()`。

## 截图工具三处修正（都在 `target/` 下，不入版本控制）
1. **必须用屏幕 DC**：`GetDC(hwnd)` 在 DWM 下返回的是重定向备份表面，窗口内容
   变了但没被判定"需要重绘"时，`BitBlt` 会**一直返回同一帧**（实测主题切了三次、
   四张图 md5 完全相同）。改成 `GetDC(0)` + 客户区屏幕坐标，抓到的才是眼前
   真正显示的东西。
2. **截图前置顶**：`SetWindowPos(HWND_TOPMOST)` 再摘掉，比单靠
   `SetForegroundWindow` 可靠（后者会被前台锁定拒绝）。否则被别的窗口压住时，
   抓到的会是**遮挡物**的内容（实测抓到了一整屏聊天界面）。
3. `Read` 工具会按内容去重，**同一张图换个文件名也认得出是同一张**；怀疑缓存时
   用 `md5sum` 判断最靠谱。

## 一个反复踩的构建坑
改完源码后 `cargo build --release` 报 `Finished in 0.8s`（没重新编译），
启动的还是旧界面。**别信那次"Finished"** —— `touch src/ui/chrome.rs` 强制重建，
正常应该跑 1 分钟以上。改完 UI 代码后务必确认 `ls --time-style=+%H:%M:%S`
的 exe 时间戳变了。

## 分段控件抽成共享组件（设置页「外观」与顶栏统一）
用户要求设置页的「跟随系统 / 深色 / 浅色」和顶栏长成同一个样子。

- 顶栏原来那个本地实现 `chrome::theme_switch()` 里，绘制逻辑整段**上移到
  `widgets::segmented(ui, p, labels, selected, height) -> Option<usize>`**，
  与具体业务（`ThemePref` / `App`）解耦：它只认「标签数组 + 当前序号 + 高度」。
  返回被点中的序号，这一帧没点就是 `None`。
- 高度常量 `widgets::SEGMENTED_HEIGHT = 39.0`，两处共用，别再各写一个。
- `chrome::theme_switch()` 退化成一层薄封装：主题枚举 ↔ 序号的映射 + 调
  `apply_theme`。`settings_page::appearance()` 直接调 `widgets::segmented`。
- 字号随高度自适应：`(height * 0.33).clamp(11.0, 15.0)`，控件拉高时文字不空在中间。
- **教训**：样式一旦要在两处出现，第一件事就是把它抽成组件。否则改一处忘一处，
  同一件事在界面上长出两个样子。本次是把顶栏那份**上移**而不是复制一份。
