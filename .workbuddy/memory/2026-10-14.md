# 2026-10-14 · clean_c（Windows C 盘清理工具）

## 项目定位
- Rust 2024 + eframe/egui 0.36.2 的 Windows C 盘清理 GUI，核心诉求是**安全清理**（白名单 + 默认拒绝）。
- 模块：`main / app / model / targets / scanner / cleaner / recycle / safety / settings / sysutil / theme / ui/*`。

## 本次完成的关键改动

### 1. 回收站通道彻底重写（`src/recycle.rs`）
- 弃用 `trash` crate（每个文件一次 `IFileOperation`，极慢；且本机返回 "Some operations were aborted"）。
- 改用 `SHFileOperationW` + `FOF_ALLOWUNDO`，一次调用最多携带 `BATCH_SIZE = 400` 个路径。
- **重大发现**：在本机（沙箱/受管控环境）即使文件已成功移入回收站，`SHFileOperationW` 仍会返回**虚假错误码 2**（ERROR_FILE_NOT_FOUND）。
  - 用 Python ctypes 对照实验确认：`SHQueryRecycleBinW` 的条目数与体积都正常增加（+1 条、+文件大小），文件也确实从原位置消失。
  - 结论：**不能只看返回码**。`recycle_batch` 现在以「调用后文件是否还存在」为唯一判据。
- `is_available()` 用真实探针文件探测并 `OnceLock` 缓存；`diagnose_matrix()` 用于自检时区分「Shell 接口不可用」与「仅回收站不可用」。

### 2. 清理流程改为批量删除（`src/cleaner.rs`）
- 新增 `DeleteQueue`：`push` 攒文件 → 满 `QUEUE_FLUSH = 400` 或收尾时 `flush`。
  - 回收站模式按批提交（`recycle::recycle_batch`），永久删除模式逐条删；两者失败都只跳过不中断。
  - `flush` 时**再做一次** `safety::verify`，路径越界/保护名单命中一律计 `blocked`。
- **修掉一个回归**：文件改成延迟删除后，遍历时目录里还有待删文件，`remove_dir` 必然失败。
  改为 `queue.push_dir()` 登记、`queue.finish()` 在文件全部删完后按「由深到浅」顺序清理空目录。
- `clean_single_file` → `queue_file`（校验 + 年龄过滤 + 入队）。

### 3. UI 接入回收站可用性
- 清理页策略行、确认弹窗、设置页、概览页：回收站不可用时给出橙色警示 + 「改用永久删除」一键切换。

### 4. 其他
- `walkdir` 未被使用，已从 `Cargo.toml` 移除。
- `windows-sys` features 增加 `Win32_System_Com`（`CoInitializeEx`）。

## 第三批需求（同日追加）：应用图标

用户要求把 `F:\app_icon.ico`（48×48、32bpp、单条目 BMP 格式，青柠图案）拷进项目并作为应用启动图标。

### 做法（零新增网络依赖）
1. **拷贝**：`F:\app_icon.ico` → `F:\rust\clean_c\assets\app_icon.ico`（MD5 一致）。
2. **窗口/任务栏图标**（`src/main.rs`）：
   - `const APP_ICON_BYTES: &[u8] = include_bytes!("../assets/app_icon.ico")`，编译期打进 exe，单文件分发不丢图标。
   - `decode_ico()` 用 `image` crate 的 `ico` feature 解码 → `egui::IconData`。
   - `image` 本来就在依赖树里（eframe → arboard → image），`ico = ["bmp", "png"]`，png 已开，等于零成本。
   - `app_icon()` 解码失败时退回原来的 `make_icon()`（像素绘制，保留作兜底）。
3. **exe 文件图标**（新增 `build.rs`）：
   - 不用 `winres`/`embed-resource`（registry 缓存里没有，要联网）——直接调 **Windows SDK 自带的 `rc.exe`**。
   - `find_rc()` 依次找：环境变量 `RC`/`RC_x86_64_pc_windows_msvc`/`RCC` → `Windows Kits\10\bin\<版本>\{x64,x86,arm64}\rc.exe`（按版本号降序）→ PATH。
   - 在 `OUT_DIR` 写 `clean_c_icon.rc`（内容 `1 ICON "<绝对路径，正斜杠>"`，注意 rc 字符串里 `\` 是转义符）→ `rc /nologo /fo ...res` → `cargo:rustc-link-arg=<res 路径>`（MSVC link.exe 直接吃 .res）。
   - **任何一步失败都只打 `cargo:warning` 然后跳过**，不影响构建；窗口图标走运行时加载，与此无关。
   - `cargo:rerun-if-changed=assets/app_icon.ico`。
4. 自检（`--selftest`）新增一行：`程序图标 : 48×48（来自 assets/app_icon.ico，已嵌入可执行文件）`。

### 验证（两套独立证据）
- **PE 资源段**：纯 Python 按 PE 规范解析 exe 的 `.rsrc` —— 有 `RT_ICON(3)` + `RT_GROUP_ICON(14)`，
  组目录 1 条目 48×48/32bpp/9640 字节，**与源 .ico 的图像数据逐字节一致**（debug 和 release 都验了）。
- **窗口实际图标**：`SendMessageW(WM_GETICON)` 拿 HICON → `GetIconInfo`/`GetDIBits` 取像素 → 导出 PNG 与源文件对比：
  是同一颗青柠，尺寸为系统缩放后的 32×32（大）/16×16（小），**属正常行为**（Windows 把 48×48 缩到系统图标尺寸）。
- 标题栏特写截图确认图标清晰显示。
- `cargo build` / `--release` / `cargo test`（14 项）全过，**零告警**。

### 踩坑记录
- **ctypes 回调（EnumResourceNamesW）会让这套受管 Python 直接崩**（`Fatal Python error: _PyThreadState_Attach`）——
  别用回调式 Win32 枚举，改成纯结构解析 PE 即可。
- ctypes 里 `GetIconInfo`/`GetClassLongPtrW` 在 **user32**，`DeleteObject`/`DeleteDC` 在 **gdi32**，写错 dll 会 AttributeError；
  所有句柄参数必须声明 argtypes，否则 64 位句柄 `int too long to convert`。
- Python 截图/读位图拿到的是 **BGRA**，写 PNG 前要换通道，否则红蓝颠倒。

- `src/safety.rs`：`SEP` 常量（Win `\` / unix `/`）、`CASE_INSENSITIVE = cfg!(any(windows, target_os="macos"))`。保护名单按平台三套（`PROTECTED_USER_SUBDIRS_{WINDOWS,MACOS,LINUX}`），静态 `PROTECTED_TREES_STATIC` 同时收录三个平台的相对片段。
- `src/targets/{mod,windows,macos,linux}.rs`：白名单按平台拆文件，`targets::build()` 分发。macOS 走 `~/Library/Caches`、`~/Library/Logs`、废纸篓、浏览器缓存、Xcode DerivedData；Linux 走 `~/.cache`、`/var/cache/*`、`/var/log`、`/tmp`、pacman/dnf/zypp。
- `src/recycle.rs`：unix 分支**纯 Rust**（同设备 `rename` 进回收站目录，跨设备退回 `fs::copy`+`remove_file`，目录与符号链接在跨设备时拒绝），**不调用任何外部命令**（不依赖 `gio trash`/`osascript`，也避免 macOS 自动化授权弹窗）。Linux 会写 XDG `.trashinfo`（含 URL 百分号转义）。
- `src/apps.rs`：`InstalledApp.uninstall_string` → `uninstall: UninstallAction{Vendor|TrashBundle|PackageManager|None}`；新增 `short_label()/description()/always_needs_root()/uninstall_display()`。macOS 扫 `/Applications` 等目录读 `Info.plist`（二进制 plist 用 `plutil -convert xml1 -o -` 转换）；Linux 解析 `/var/lib/dpkg/status` + `snap list` + `flatpak list`，卸载走 `pkexec`。
- `src/theme.rs`：字体探测按平台 —— Windows `windows_dir()/Fonts`；macOS `PingFang.ttc`/`Hiragino Sans GB.ttc`；Linux 常见路径 + `scan_font_dirs()` 递归兜底，并用 `clamp_face_index()` 读 TTC 头把 face 索引收进合法范围（Noto CJK 合集里简体在索引 2）。
- `src/advice.rs`：`CACHE_MARKERS`/`SYSTEM_MARKERS` 同时收 Windows 反斜杠与 Unix 斜杠两套；`dir_key()` 用 `safety::SEP`；新增 unix 安装包后缀（appimage/flatpak/snap/run）与 unix 库后缀（so/dylib/ko/a）。
- `Cargo.toml`：新增 `[target.'cfg(unix)'.dependencies] libc`（零新 crate）；**新增 `[target.'cfg(target_os="linux")'.dependencies] eframe`，补 `x11`/`wayland` 特性** —— `default-features = false` 把这两个特性关掉了，Linux 上 winit 会直接 `compile_error!`。

### 两个真实 bug（交叉编译抓出来的）
1. **`C:/Windows` 被整棵拉黑**：`protected_trees()` 里有一句 `for sub in ["", ...] { out.push(format!("{win}{sub}")) }`，push 了空 sub ⇒ `c:/windows` 成了保护树 ⇒ `C:/Windows/Temp`、`C:/Windows/Logs`、`C:/Windows/Prefetch`、`C:/Windows/SoftwareDistribution/Download`、`C:/Windows/Minidump` 这些**清理目标一个文件都删不掉**（`--dryrun` 会报大量安全拦截）。修法：删掉空 sub，改为给静态片段补**真实系统盘符**（`system_drive()` 从 `%SystemRoot%` 反推，系统盘不一定是 C:），并补 `\windows\microsoft.net`、`\windows\system32\{spool,wbem,winevt,msdtc,oobe,smi,licensing,migration,recovery,advancedinstallers,logfiles}` 等敏感子目录。验证：`--dryrun` 安全拦截恢复为 0。
2. **`recycle.rs` 残留 `platform_tool_delete()`** 引用已删除的 `native_trash_tool()`。Windows 上看不出来（函数带 `#[cfg(unix)]`），Linux 交叉编译才暴露。整段删掉。
