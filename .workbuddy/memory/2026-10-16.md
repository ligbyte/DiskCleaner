## 三件事的落点

       填充按 `FILL_INSET = 0.5` 内缩，让硬边正好接上羽化环 alpha=1 的内边。

**踩坑**：`FILL_INSET` 试过 1.0，RMS 反而涨到 0.407 —— 填充退太多，和只覆盖

## 顺手修掉的滚动条压内容（排查锯齿时被它坑了半小时）
`ScrollStyle::floating()` 的 `floating_allocated_width` 默认是 **0.0**：滚动条
**不占布局宽度**，直接浮在 ScrollArea 最右边那几个像素上。而 CentralPanel 的内边距
和 ScrollArea 严丝合缝，于是这条 2px（悬停展开 10px）的灰条正好压在按钮右圆角上。
后果：静止截图里它淡出到全透明，**一滚动就冒出来**，把亚像素圆拟合的残差从
0.039px 抬到 **0.376px**，我一度以为修好的羽化回退了，白查半天。

修法（`app.rs`）：`ui.style_mut().spacing.scroll.floating_allocated_width = 12.0`，
同时把 CentralPanel 内边距右侧从 22 改成 10 —— 内容右边界仍是 `1120−22 = 1098`，
**逐像素没动**（改前改后按钮 bbox 都是 `x914..1097 / y130..181 / 8659 像素`，
整页差异只有最右一列 17 个像素）。滚动条从 x1096..1097 挪到 x1108..1109，
和内容之间留 11px，悬停展开也碰不到。
`floating_allocated_width` 是**静态**量（只看"是否需要滚动"，不跟淡入淡出动画走），
所以留过道不会让内容左右抖动 —— 我原本想用"加大 frame 内边距"来留，
那是错的方向：frame 内边距会**连 ScrollArea 一起**往里挪，内容照样贴着滚动条。

# 第三轮：侧栏「系统」分组（设置 / 安全说明）

## 用户报的问题
「左侧的侧边栏：系统 下面的 设置、安全说明，布局不够美观」

## 量出来的真实毛病（先量再改，没靠眼睛猜）
用 `PrintWindow` 抓图后逐行量侧栏（`item_spacing` 全局是 8，条目高 34、间距 2）：

| 元素 | 改前 | 改后 |
|---|---|---|
| 分隔线 | 无 | y610，x25..186（两端内缩 13） |
| 「系统」标题 | ink y660-671 | y636-647 |
| 设置 | 条目 rect 684..718 | 660..694 |
| 安全说明 | 条目 rect **728..762** | 704..738 |
| 窗口底 | 760 | 760 |

**「安全说明」的条目 rect 底在 762 —— 溢出侧栏内容底（748）14px，
还越过窗口底（760）2px。** 选中/悬停的胶囊会直接被窗口边缘切掉。
根因：`chrome::group_height()` 手算「一组的高度」时写成
`34 + n×(34+2)`，漏掉了 egui 在**每个 `allocate_*` 之后**追加的
`spacing.item_spacing`（本程序全局设成 8）；一个 2 条目的组实际是 130 不是 106。
沉底用的 `add_space(可用高度 − 组高)` 因此少留了 24px。

## 改法
1. **不再手算高度**：把最后一组塞进嵌套的
   `Panel::bottom("cleanc_nav_footer")`（`resizable(false)`、`show_separator_line(false)`、
   `Frame::new().fill(p.nav_bg)` 无 margin）。面板高度按内容自适应，而且会把空间
   从父级扣掉，所以**再矮的窗口也不会和上面几组重叠**（原来手算的写法会叠上去）。
   上一组的效果：顶部几组照旧自上而下。
2. **加一条页脚分隔线** `widgets::nav_separator` + 新调色板字段 `nav_line`。
   它给「系统」上方那 270px 空白一个交代 —— 否则那个 11px 的灰标签像是
   孤零零飘在侧栏中间，这正是"不美观"观感的主要来源。
   颜色按可见度挑过：`p.border` 在侧栏底上只有 Δ13（几乎看不见），
   所以浅色用 `#CDD8E7`（Δ40）、深色用 `#242C37`（Δ83），
   与主区 `border` 在两个主题下的可见度相当。
3. **把留白收敛到一处**：`widgets::nav_group` 原来自带 `add_space(12)/add_space(2)`，
   调用方想算高度就得把这几个数再抄一遍（就是上面那个 bug 的温床）。
   现在 `nav_group` 只画标题，留白由 `chrome::nav_group_block` 统一给，
   常量提到 `widgets::{NAV_GROUP_TOP, NAV_GROUP_UNDER, NAV_GROUP_LABEL_H}`。
   `group_height()` 和 `NAV_GROUP_HEIGHT` 一起删掉。
4. 顺手把 `nav_item` 里的局部 `ICON_LEFT/ICON_SIDE` 提成
   `NAV_ICON_LEFT/NAV_ICON_SIDE`，让分组标题、图标列、分隔线内缩共用同一个数。

## 踩/验
- **页脚里再 `add_space` 一次会把留白叠成两倍**：第一版我加了
  `NAV_FOOTER_TOP = 14`，而 `nav_group_block` 里已经有 `NAV_GROUP_TOP = 12`，
  实测分隔线到标题之间多出 12px（分隔线跑到 596，本该 610）。删掉即可。
- 验证矩阵：三平台 `cargo check` 零告警、`cargo test` 43 全过、`--dryrun` 拦截 0、
  `--selftest` 回收站可用。
- 截图验证（**五页** 概览/智能清理/大文件/软件卸载/设置 各抓一张，
  用 `PrintWindow` 抓客户区）：
  - 分隔线都是 y610 x25..186；页脚三行都是 636-647 / 670-685 / 714-729；
  - `y748..760` 侧栏区非底色像素 **0**（不再溢出）；
  - 五页主内容区两两差异都 >13 万（说明点「设置」「安全说明」都能翻页 ——
    嵌套面板里的命中区确实生效，这条必须实测，不能想当然）；
